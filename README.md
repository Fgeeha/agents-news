# agents-news

Группа LLM-агентов, которая парсит новостные RSS-ленты и переписывает каждую
новость под свою тему: агент-агроном — для аграриев, агент-айтишник — для IT,
агент-медик — для темы здоровья. Если новость не относится к области агента —
агент её пропускает. Отдельный агент-рецензент на **другой модели** проверяет
каждую статью, чтобы не «подсуживать» своим.

Проверено экспериментально на локальном стеке: Ollama + LiteLLM proxy,
модели `qwen2.5:14b-instruct-q4_K_M`, `qwen2.5:7b-instruct`, `gemma2:9b`.

## Архитектура

```text
RSS-ленты ──> feeds.py ──> дедупликация: id -> Жаккар -> эмбеддинги -> LLM
                           (state/seen.json)
                ──> догрузка полного текста, если RSS-описание короткое
                               │
                для каждой новости × каждого эксперта
                               │
                ┌──────────────▼───────────────┐
                │ 1. Фильтр релевантности      │  модель gate (дешёвая)
                │    «ДА/НЕТ» — тема эксперта? │  НЕТ -> пропуск, ничего не делаем
                └──────────────┬───────────────┘
                               │ ДА
                ┌──────────────▼───────────────┐
                │ 2. Переработка экспертом     │  модель expert
                │    статья для своей аудитории│
                └──────────────┬───────────────┘
                ┌──────────────▼───────────────┐
                │ 3. Независимая проверка      │  модель reviewer
                │    (ДРУГОЕ семейство моделей)│  вердикт ПРИНЯТО/ОТКЛОНЕНО
                └──────────────┬───────────────┘
                               ▼
                out/ГГГГ-ММ-ДД/<эксперт>/<новость>.md

Все вызовы LLM ──> шлюз LiteLLM (localhost:4000) ──> Ollama (localhost:11434)
```

## Почему шлюз (LiteLLM)

Код пайплайна ходит в **один** OpenAI-совместимый endpoint и оперирует только
алиасами моделей (`gate`, `expert`, `reviewer`). Что стоит за алиасом — решает
`litellm.config.yaml`:

- **Замена модели без правки кода.** Перевести рецензента с `gemma2:9b` на
  GPT/Claude/другую локальную модель — одна строка в конфиге шлюза.
- **Смешивание провайдеров.** Эксперты — локально в Ollama, рецензент — во
  внешнем API (или наоборот): пайплайн этого не видит.
- **Независимость рецензента.** Разные роли жёстко разведены по алиасам, поэтому
  «рецензент = другое семейство моделей» — свойство конфигурации, его нельзя
  случайно сломать в коде.
- Бонусы LiteLLM при росте: fallback-модели, rate limiting, учёт затрат, логи.

Альтернативы шлюзу: прямой endpoint Ollama (`http://localhost:11434/v1`) — тогда
в `config.yaml` вместо алиасов пишутся реальные имена моделей, а LiteLLM не
нужен вовсе (код не меняется); либо OpenRouter — тот же OpenAI-совместимый
интерфейс поверх облачных моделей.

## Роли агентов

| Роль | Алиас | Модель (по умолчанию) | Задача |
|------|-------|----------------------|--------|
| Фильтр | `gate` | `qwen2.5:7b-instruct` | Быстрый ответ «ДА/НЕТ»: относится ли новость к теме эксперта |
| Эксперты (агро, IT, здоровье) | `expert` | `qwen2.5:14b-instruct-q4_K_M` | Переписать новость для своей аудитории, только факты из исходника |
| Рецензент | `reviewer` | `gemma2:9b` | Сверить статью с исходником: выдумки, искажения, соответствие теме |
| Эмбеддинги | `embed` | `bge-m3` | Векторы заголовков для поиска дублей между сайтами |

Рецензент — семейство Gemma (Google), эксперты — Qwen (Alibaba): модель одного
семейства склонна одобрять «свои» тексты, разное семейство снижает этот сдвиг.

## Запуск

```bash
make install     # зависимости (uv)
make gateway     # терминал 1: шлюз LiteLLM на :4000 (нужен запущенный Ollama)
make run-once    # терминал 2: пробный прогон — 1 новость, без записи состояния
make run         # боевой прогон: все новые новости из лент
make test        # тесты (без сети и LLM)
```

Результат — Markdown-файлы в `out/ГГГГ-ММ-ДД/<эксперт>/` с frontmatter:
источник, модели, вердикт рецензента; в конце файла — его замечания.
Статьи, которые рецензент **отклонил**, сохраняются в подпапку
`out/ГГГГ-ММ-ДД/<эксперт>/rejected/` — пайплайн предупреждает об этом в логе
(`WARNING`) и в итоговой строке запуска, замечания рецензента внутри файла.

Если RSS-описание короче 200 символов (типично для kremlin.ru частично и
government.ru целиком), перед обработкой догружается полный текст страницы
(trafilatura, до 4000 символов) — эксперт и рецензент работают с настоящим
исходником, а не с одним заголовком.

## Дедупликация

Все уровни опираются на `state/seen.json` (сбросить — `rm -rf state` или
`--no-state`):

1. **По id/ссылке** — одна и та же новость не обрабатывается повторно между
   запусками.
2. **По заголовку, каскадом** — один сюжет с разных сайтов отсеивается
   (`feeds.Deduper`, сравнение с последними 500 обработанными заголовками):
   - Жаккар по значимым словам ≥ 0.6 → дубль (ловит перестановки слов,
     бесплатно);
   - иначе косинус эмбеддингов `bge-m3`: ≥ 0.85 → дубль, < 0.55 → не дубль;
   - серая зона [0.55, 0.85) → gate-модель отвечает, одно ли это событие.
   Пороги откалиброваны на реальных парах заголовков 2026-08-17: пересказы
   одного события дают косинус 0.52–0.99, разные события той же темы —
   0.44–0.69, поэтому без LLM-подтверждения серую зону не разделить.
   При недоступности эмбеддингов детектор деградирует до одного Жаккара
   с предупреждением в логе.

## Как добавить эксперта или ленту

Только `config.yaml`, код не трогается:

```yaml
experts:
  - name: finance
    title: Эксперт по финансам
    domain: экономика, банки, инвестиции, криптовалюты, рынки
    model: expert          # или отдельный алиас из litellm.config.yaml

feeds:
  - https://www.finam.ru/analysis/conews/rsspoint/
```

Сейчас подключены (все проверены на валидный RSS 2026-08-17):

- федеральные СМИ: lenta.ru, habr.com;
- волгоградские СМИ: v1.ru, bloknot-volgograd.ru, vpravda.ru,
  volgograd.kp.ru, riac34.ru;
- госисточники: volgoduma.ru (облдума), kremlin.ru, government.ru.

У госновостей RSS-описание часто пустое (government.ru — всегда, kremlin.ru —
у части записей) — для них автоматически догружается полный текст страницы.
RSS проверялись также у volgograd.ru, volgadmin.ru, 34.mchs.gov.ru,
duma.gov.ru, mcx.gov.ru, minzdrav.gov.ru, digital.gov.ru,
34.rospotrebnadzor.ru — лент у них нет.

Отдельная модель для конкретного эксперта — новый алиас в
`litellm.config.yaml` + его имя в поле `model` эксперта.

Локальному шлюзу аутентификация не нужна; если LiteLLM развёрнут с
`LITELLM_MASTER_KEY`, ключ для пайплайна задаётся переменной окружения
`LITELLM_API_KEY` (не в `config.yaml`).

## Ограничения MVP и куда развивать

- Полный текст догружается только при коротком RSS-описании (< 200 символов);
  для остальных используется описание из ленты. Дальше: догружать всегда.
- Вердикт «ОТКЛОНЕНО» уводит статью в `rejected/`, но не запускает
  переписывание. Дальше: цикл эксперт→рецензент до принятия (с лимитом
  итераций).
- Фильтр релевантности — один вызов «ДА/НЕТ» на пару новость×эксперт. Дальше:
  классифицировать новость по всем темам одним вызовом или эмбеддингами.
- Запуск ручной. Дальше: cron/systemd-timer на `make run`.
